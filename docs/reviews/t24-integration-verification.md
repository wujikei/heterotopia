# T24 integration gate investigation

## Sprite contract mismatch, reproduced and corrected
PR17 deliberately keeps opaque character bodies opaque during narration, dimming the image with a brightness filter instead of alpha. The old test still waited for wrapper opacity exactly 0.55. Unchanged local and GitHub runs time out at this condition. The updated check requires wrapper opacity >=0.99 and image brightness <1, while keeping the exact same DOM-node continuity, return-to-speaking and transition checks. The full sprite suite passes locally after the change. Restoring the old alpha behavior now fails the updated check.

## Offline CI investigation, not assumed flaky
Main run 45328851006 timed out after a quality-mode reload at test-portable.mjs:203. Its artifact has no browser/network errors, but settings lightweight=false and original hero art; the existing evidence cannot identify the writer. The unchanged local suite passed that point and then exposed a separate readiness race: isEnabled was read immediately after reload before lazy story readiness, at line 250. A full instrumented run passed, and a separate repeated offline quality/reload probe records settings writes. No product setting-persistence change is justified yet. The readiness test now waits for the existing continue button to become enabled, then still asserts it. Navigation-time fixture/settings diagnostics are retained on failure so another real persistence failure is actionable. No timeout increased, assertion removed, workflow changed or scenario skipped.

Disposable fixtures only; no real player saves. CI must pass on the actual PR head before merge, followed by a fresh main deployment and live asset verification.

## File-origin storage premise falsified by PR18 diagnostics
PR18 run 45334574476 failed at the continuation check despite the readiness wait. Context 0 logged persisted lightweight=true on its first reload, then null before application startup on its next reload. The fixture consequently re-seeded default settings and there was no save to continue. This locates the failure before application code. No application storage-clear or remove-item call exists. A blank-file probe, with sibling-context disposal and simulated memory pressure, did not reproduce it locally. We do not claim to know Chromium's internal eviction path or label the result flaky.

The persistence goal now uses an isolated temporary on-disk Chromium profile, rather than relying on incognito file-origin storage. The full test still uses file:// with networking disabled. It retains all reload, quality, asset, audio, import/export and save assertions. It additionally closes the entire persistent browser process, opens the same disposable profile without any fixture or storage-state injection, and verifies that the actual autosave, bookmark and quality setting were recovered from disk. Other asset fixtures remain isolated incognito contexts. The temporary profile is closed and removed after testing; no personal browser profile is opened.

MDN documents that file-URL localStorage requirements are undefined and browser-dependent: https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage . This test validates the supported ordinary Chromium profile path, not a guarantee for every browser's private mode. Offline users should export saves before moving files, changing browsers, or using private browsing. Browser-internal eviction remains outside the application's control.
